# Рабочий стол, мышь и разрешения 0.6

Версия добавляет полноценное управление внутренними окнами оболочки мышью,
сглаженный интерфейс с кириллицей и выбор видеорежима до запуска ядра.
Микроядерное разделение сохраняется: IRQ-stubs и выдача ресурса находятся
в ядре, разбор клавиатуры/мыши — в процессе 3, оболочка и композиция — в процессе 4.
Это три внутренних окна одного процесса, не отдельные прикладные процессы.

## Мышь

При загрузке с IF=0 ядро сохраняет настройки 8042, временно останавливает порты,
включает aux-port, отключает поток мыши, задаёт defaults и выполняет
IntelliMouse negotiation 200/100/80 + Read ID. Поддерживаются ID 0 (3 байта),
ID 3 (4 байта, 8-битное колесо) и ID 4 (4 байта, 4-битное колесо).
Настройки задают 100 reports/sec, resolution 4 counts/mm и Stream Enable.
Команды ограничены polling-budget и тремя retries для RESEND. При отсутствии
ответа aux-port отключается, клавиатура остаётся доступной.

PIC включает IRQ0/1/2 и при успешной инициализации IRQ12. Обе PS/2 IRQ-entry
сохраняют все общие регистры; общий обработчик различает источник по aux-bit,
складывает байты в отдельные очереди ёмкостью 255 и подтверждает slave/master EOI
для IRQ12. Пользовательские процессы не получают доступ к портам.
Отдельные IRQ7/IRQ15 handlers проверяют ISR и игнорируют ложные запросы PIC;
для ложного slave IRQ подтверждается только cascade на master.
Поведение сверено с [Intel 8259A datasheet](https://courses.cs.washington.edu/courses/cse451/25wi/documentation/8259A.pdf).

Вызов 7 доступен только процессу 3: аргумент 0 читает mouse byte, 1 — device ID,
2 — счётчик потерянных байтов. Вызов 6 дополнен аргументом 1 для keyboard loss.
Служба ввода разбирает 9-битные X/Y, инвертирует Y для экранных координат,
передаёт три кнопки и колесо; overflow отбрасывает движение, сохраняя кнопки.
При потере байтов декодер сбрасывает незавершённый пакет. Синхронизация ищет
header bit 3; это базовый режим, без аппаратного сброса устройства в ходе работы.

Mouse IPC использует bit 63 как тип события, далее signed i16 X/Y, signed i8
колесо и три button bits. Остальные биты должны быть нулевыми. Рабочий стол
проверяет тип, диапазон и sender 3. Клавиатурные события сохраняют прежние
числовые значения; F3 добавлен как событие Settings.

PS/2-мышь и PS/2-compatible relative touchpad — текущие цели. Native USB HID,
абсолютный Synaptics/ALPS-протокол, multitouch и hotplug ещё отсутствуют.
USB-мышь возможна только при эмуляции PS/2 firmware; это отдельно не проверено.

Форматы пакетов и negotiation сверены с [документацией Microsoft](https://learn.microsoft.com/en-us/windows-hardware/drivers/hid/keyboard-and-mouse-hid-client-drivers#activating-buttons-4-5-and-wheel-on-ps2-mice).

## Видеорежим

Загрузчик перечисляет VBE mode list с ограничением обхода, фильтрует 32-bit
direct color/LFB, RGB masks, размеры 800–1920 × 600–1200, pitch и span до 16 МиБ,
без выхода физических адресов за 4 ГиБ. Для VBE 3 используются linear pitch/masks.
Одинаковые размеры не дублируются. Сохраняются двенадцать лучших режимов;
самый маленький допустимый режим хранится отдельно для F1.

VBE/DDC Read EDID проверяет заголовок, checksum и первый detailed timing.
Совпадающий с native active size режим имеет приоритет; без этого совпадения
рейтинг определяется площадью. Родное разрешение вне допустимых размеров
или без подходящего 32-bit VBE режима не может быть выбрано.

Меню работает через BIOS INT 10h/16h до long mode: стрелки, Enter,
F1 для safe mode и Esc для default. Без клавиш запускается default примерно
через пять секунд по BIOS ticks. После первого нажатия timeout отменяется.
При ошибке SetMode загрузчик ограниченно пробует остальные сохранённые режимы,
затем использует текстовый fallback. Клавиатура остаётся способом отката,
если на новом разрешении возникнут артефакты.

В «Настройках» показывается фактическое разрешение и способ его смены при
следующей загрузке. Live mode switching после выхода из BIOS, persistence
выбора и собственный display driver ещё не реализованы.
Поля и функции сверены с [VESA VBE 3.0 specification](https://courses.cs.washington.edu/courses/cse451/20wi/readings/vbe3.pdf).

## Композиция и окна

Только рабочему столу выдаётся writable uncached framebuffer mapping и новый
writable cached RAM backbuffer по USER_BASE + 32 МиБ. Startup расширен до 32 байт
полем backbuffer; stride RAM равен ширине, stride framebuffer берётся из BIOS.
На 1920×1200 RAM-буфер занимает около 8.8 МиБ. Другие процессы не получают
его отображения. Ресурсы остаются занятыми до перезагрузки.

Сцена содержит три окна: «Система», «Настройки», «Помощь». Окна имеют порядок
перекрытия, фокус, независимое положение, минимальный размер, свёрнутое и
развёрнутое состояние. Заголовок перемещает окно, правый нижний угол меняет размер.
Кнопки и панель задач открывают/сворачивают/возвращают/закрывают окна.
Значки открываются двойным щелчком; правая кнопка на свободном фоне открывает меню.
Колесо прокручивает справку. Позиции окна и указателя ограничены рабочей областью.

«Настройки» меняют тему, четыре accent colors, скорость указателя 1x–3x,
запрашивают проверку памяти и показывают текущий размер экрана/готовность PS/2.
Настройки действуют до перезагрузки. Приложения с файлами пока отсутствуют.

Перерисовка использует объединённый damage rectangle и clipping всех операций.
Сцена рисуется в RAM, затем повреждённая область копируется в framebuffer.
Курсор накладывается только на framebuffer; старое место восстанавливается
из RAM, чтобы не оставлять следов. Движение курсора само по себе не перерисовывает
всю сцену. Hover, темы, перемещение и размер окон отмечают свои повреждённые области.
Рамки меню и изменение кнопки Start также участвуют в damage.

Present ограничен двумя PIT ticks (целевой верхний предел примерно 50 обновлений/с),
диагностика обновляется каждые 20 ticks. Реальная скорость зависит от CPU и
framebuffer bandwidth; измерение в «Системе» включает прерывания и округлено
до 10 мс, это не доказательство 50 FPS на ноутбуке.

GetStatus расширен полями 15 mouse ready, 16 mouse loss, 17 mouse packets,
18 mouse ID и 19 ticks последнего обновления. Report процесса 4 передаёт это
время в RSI, остальных процессов — 0. Все прежние проверки памяти/IPC/изоляции
продолжаются. NX не изменён.

## Шрифт и проверка

Используется 4-bit alpha atlas hpOS Interface, производный от Noto Sans OFL 1.1.
Он содержит ASCII и кириллицу; alpha blending выполняется целыми числами в RAM.
Лицензия, происхождение и генератор описаны в [dependencies.md](dependencies.md).

Тесты включают mouse sign/overflow/wheel и формат IPC, управление окнами,
экстремальные координаты указателя, pitch/clipping/blit, ориентацию атласа
и точное сравнение частичного обновления с полной сценой после действий.
Превью используют тот же renderer в 800×600, 1024×768, 1440×900 и 1920×1080
с двумя темами и несколькими окнами/меню. Счётчики в превью примерные.

На железе требуется новая проверка `build/hpos-0.6.img`:

1. В меню загрузчика выбрать разрешение выше 800×600; сфотографировать список,
   если родного режима нет. При проблемах перезапустить и выбрать F1 safe mode.
2. Проверить курсор тачпадом/PS/2-мышью, щелчки и отсутствие следов курсора.
3. Открыть значки двойным щелчком, несколько окон одновременно; поменять фокус.
4. Перетащить окно, изменить размер за угол, свернуть, вернуть через панель,
   развернуть и закрыть. Проверить чистоту фона и перекрытий.
5. В настройках щёлкнуть обе темы, цвета и скорости; нажать проверку памяти.
6. Прокрутить справку колесом, открыть/закрыть меню мышью и клавиатурой.
7. В «Системе» проверить IPC OK, ISOLATION OK, MEMORY OK, INPUT OK и растущие
   счётчики мыши/кадров; отсутствие QUEUE OVERFLOW/PROCESS FAULT.

Версия 0.5 сохранена в `build/verified-0.5/hpos.img` для отката.
