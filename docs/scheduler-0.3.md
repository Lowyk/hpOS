# Потоки и таймер 0.3

## Модель выполнения

Это четыре потока ядра на одном начальном CPU в общем адресном пространстве:
интерфейс, две демонстрационные задачи и idle. Они не являются изолированными
пользовательскими процессами. Потоки фиксированы при загрузке; создание,
завершение и освобождение ресурсов потока во время работы пока не реализованы.

Общая политика `hpos-scheduler` не содержит аппаратных инструкций. Она отслеживает
ready/running/sleeping и выбирает следующую готовую задачу по кругу.
Idle выбирается только при отсутствии готовой обычной задачи. PIT channel 0
в режиме 2 генерирует IRQ0 примерно 100 раз в секунду; квант — два тика.
Проснувшаяся задача становится готовой на своём deadline. Сравнение deadline
учитывает переполнение 64-битного счётчика для интервалов короче 2^63 тиков.

Демонстрационные задачи активно считают примерно три тика wall time,
не уступая CPU внутри этого цикла, затем спят пять тиков. Таким образом,
их активный цикл может быть вытеснен таймером. Idle ждёт прерываний через HLT.
Интерфейс засыпает на один тик и обновляет только области счётчиков примерно
10 раз в секунду. Полный экран перерисовывается при переключении темы и M.

## Контекст x86_64

IRQ0 и программный `INT 0x30` сохраняют 15 общих регистров в одном порядке.
В long mode аппаратный кадр содержит RIP, CS, RFLAGS, RSP и SS, в том числе
при отсутствии смены CPL. Поэтому собственный кадр занимает 160 байт.
Перед вызовом Rust stack pointer явно выравнивается на 16 байт.
Переход к следующему контексту заменяет RSP, восстанавливает общие регистры
и выполняет IRETQ. Эти правила соответствуют
[Intel SDM, разделам 6.14.2–6.14.3](https://cdrdv2-public.intel.com/812386/253668-sdm-vol-3a.pdf).

Дополнительно выполняются FXSAVE64/FXRSTOR64 для отдельного 512-байтного,
выровненного на 16 байт буфера каждого потока. При инициализации очищается TS,
инициализируются x87 и MXCSR. Rust-код обработчика для bare-metal target
компилируется без SSE/AVX; это проверено через `rustc --print cfg` с параметрами
сборки. Автоматическое использование SIMD компилятором внутри обработчика
нельзя включать без пересмотра границы сохранения состояния. AVX/XSAVE
контекст в этой версии не используется и не проверяется.

Поток интерфейса сохраняет прежний 64-КиБ загрузочный стек. Три новых потока
получают по 16 КиБ в диапазоне виртуальных адресов выше 4 ГиБ с отсутствующими
страницами до и после стека. Для первого входа создаётся искусственный IRQ-кадр
с IF=1 и SysV-выравниванием RSP. Тестовые задачи получают номер в RDI.

Мутация структуры планировщика происходит с IF=0. При сне IF отключается
до изменения состояния; mutable borrow завершается перед `INT 0x30`.
После возобновления восстанавливается исходное разрешение прерываний.
IRQ0 получает EOI перед возвратом в выбранный поток; программный yield EOI не посылает.
Снимки для экрана и события клавиатуры используют отдельные атомарные значения.
MemoryManager остаётся только у потока интерфейса: IRQ и тестовые задачи
не используют его аллокатор.

## Что проверять на ноутбуке

- Обе задачи увеличивают счётчики при наблюдении несколько секунд.
- TICKS и SWITCHES продолжают расти.
- Появляется CONTEXT OK; CONTEXT ERROR отсутствует.
- T переключает обе темы, пока задачи продолжают работать.
- M увеличивает CHECKS, объём свободной памяти после повторов остаётся прежним.

Каждая задача хранит ожидаемые значения R12, R14, RBX и XMM0 на собственном
стеке и сверяет их внутри активного цикла. Ошибка устанавливает общий sticky-флаг,
который экран показывает как CONTEXT ERROR. Такой probe обнаруживает часть
ошибок сохранения контекста, но не является полной проверкой всех регистров,
всех прерываний или длительной стабильности.

Проверка host-тестами охватывает только политику выбора потоков. Формат контекста
проверяется compile-time assertions, инструкции дополнительно просмотрены в LLDB.
Аппаратный результат 0.2 к новой версии не относится.
