# Сеть и браузер (0.10)

Интернет берётся у телефона через USB-модем (RNDIS). Новые окна
«Сеть» (F8) и «Браузер» (F7), команды терминала `connect`, `net`, `ping`, `open`.
На железе пока не проверялось.

## Как подключиться

1. Загрузите hpOS и откройте «Сеть» (F8), нажмите «Подключить» (или Enter).
   До этого USB остаётся у BIOS: ОС забирает контроллер только по команде.
2. Подключите телефон кабелем к ноутбуку.
3. На телефоне включите USB-модем. На Huawei/HarmonyOS: Настройки →
   Мобильная сеть → Режим модема → USB-модем.
4. В окне «Сеть» стадия меняется: «Ждём телефон» → «Знакомимся с
   устройством» → «Телефон на связи» → «Получаем адрес» → «В сети».
5. Откройте «Браузер», введите адрес (`example.com`) или запрос (`котики`) и
   нажмите Enter.

Если что-то не так, пришлите фото окна «Сеть»: журнал внизу показывает,
на каком шаге остановилось (контроллер, порт, устройство, RNDIS, DHCP).
В журнале у устройства пишется `vendor:product`. Если там «Не модем (класс ...)»,
телефон подключён, но USB-модем на нём не включён или работает не через RNDIS.

Загрузка через Ventoy + Memdisk для этого обязательна: образ лежит в памяти,
и BIOS не нужен USB. Если записать образ на флешку через dd, диск после
включения сети пропадёт, потому что USB-контроллер забирает ОС.

## Браузер

- Только HTTP/1.1 без шифрования. HTTPS-адреса открываются через читалку
  FrogFind (`http://frogfind.com/read.php?a=...`): она сама скачивает
  HTTPS-страницу и отдаёт упрощённый текст по HTTP. Текст без точки и с
  пробелами ищется через FrogFind.
- Важно для приватности: через FrogFind страница идёт к стороннему сайту и
  дальше по сети без шифрования. Пароли и личные данные в hpOS вводить нельзя.
- Показывается текст: заголовки, абзацы, списки, цитаты, `<pre>`, горизонтальные
  линии, ссылки (с подчёркиванием, адрес видно внизу при наведении) и `alt`
  у картинок. CSS, JavaScript, картинки и формы не поддерживаются.
- Кодировки: UTF-8, windows-1251, KOI8-R/U, Latin-1. Если сервер её не назвал,
  ищется `<meta charset>`, иначе проверяется UTF-8, иначе windows-1251.
- Страница до 1 МБ (ответ сервера), текст до 512 КБ, до 4096 ссылок.
- Перенаправления (301/302/303/307/308) — до шести подряд.
- Управление: Enter в адресной строке — открыть; щелчок по ссылке; Backspace —
  назад; Ctrl+R — обновить; Esc — остановить загрузку; Ctrl+L — новый адрес;
  стрелки, PgUp/PgDn, пробел, Home/End и колесо мыши прокручивают страницу.
  Если начать печатать на странице, текст пойдёт в адресную строку.

## Устройство

### Ядро

- Ядру отведены первые 4 МиБ памяти вместо 2 МиБ: образ ядра со службами вырос
  до ~1 МБ (предел загрузчика теперь 2,9 МБ, раздел ядра — 3 МиБ).
- `kernel/src/pci.rs`: доступ к PCI (порты 0xCF8/0xCFC) и поиск контроллера
  USB 2.0 (класс 0C/03/20) с 32-битным регистром BAR0.
- Новая служба `net` (поток 6). Ей отображаются: регистры EHCI (страница без
  кэширования), 128 КиБ физически непрерывной памяти для DMA
  (`FrameAllocator::allocate_run`) и общее с рабочим столом окно 1 МиБ
  (`net::State` и тело страницы).
- Системный вызов 11 (только `net`, контроллер в битах 8–15 аргумента: 0 — EHCI,
  1–4 — UHCI): адрес DMA и положение контроллера,
  чтение конфигурации PCI контроллера, запись только регистра команд и области
  возможностей (смещения ≥ 0x40, там передача контроля от BIOS); BAR менять нельзя.
- Системный вызов 12 (только `net`): чтение и запись портов ввода-вывода,
  но только внутри регистров найденных UHCI.
- Счётчик тиков (вызов 5, аргумент 0) теперь доступен всем службам.
- После каждого вызова BIOS ядро забирает застрявшие байты из контроллера PS/2
  (исправление «ломается управление» в 0.9).

### Служба `net` (`services/src/net.rs`, `services/src/ehci.rs`)

- EHCI: передача контроля от BIOS (USBLEGSUP, ожидание до 1 с, затем силой),
  сброс, асинхронное расписание из четырёх очередей (голова, endpoint 0,
  bulk OUT, bulk IN), опрос без прерываний.
- Порт: сброс 60 мс, проверка high-speed, до трёх попыток. Если устройство
  не стало high-speed, оно отдаётся контроллеру-компаньону USB 1.1; в журнале
  видно состояние порта (PORTSC) до и после сброса.
- UHCI (`services/src/uhci.rs`, USB 1.1, до четырёх контроллеров): регистры —
  порты ввода-вывода через системный вызов 12, список кадров с тремя очередями,
  передачи из дескрипторов по одному пакету (до 64 байт). Скорость до ~1 МБ/с.
- Перечисление: дескриптор устройства, адрес 1, поиск RNDIS во всех
  конфигурациях (классы E0/01/03, 02/02/FF, EF/04/01 + интерфейс данных 0A),
  SET_CONFIGURATION.
- RNDIS: INITIALIZE (передачи до 16 КиБ), QUERY постоянного MAC (он становится
  адресом ноутбука), SET фильтра пакетов, кадры в PACKET_MSG.
- Стек `crates/net`: Ethernet, ARP, IPv4 (без фрагментов), ICMP echo, UDP,
  DHCP-клиент, DNS (A-записи, CNAME пропускаются), один TCP-клиент
  (MSS 1460, окно до 64 КиБ, повторы с удвоением тайм-аута, обрыв через 30 с
  тишины), HTTP/1.1 с `Connection: close`, chunked и перенаправлениями.

### Рабочий стол

- Команды идут в службу по IPC (`op | номер << 8`), текст запроса — в общей
  странице; служба подтверждает копирование полем `taken`.
- Состояние, журнал (64 события) и ход загрузки рабочий стол читает из общей
  страницы, когда меняется `version`.
- Страница (`crates/desktop/src/browser.rs`) живёт в куче рабочего стола
  (2 МиБ из 4 МиБ): HTML → блоки и строки текста → раскладка по ширине окна.

## Проверено и не проверено

Проверено на Mac тестами: разбор дескрипторов USB и сообщений RNDIS, стек
целиком против поддельного «телефона» (DHCP, ARP, ping, DNS с CNAME, загрузка
страницы с потерей пакета и повтором, переполнение буфера, тайм-аут), HTTP,
разрешение ссылок, разбор HTML и кодировок, раскладка, клавиши и щелчки браузера,
частичная перерисовка новых окон.

Не проверено (только железо): драйверы EHCI и UHCI, передача контроля от BIOS на
Toshiba P100, поведение RNDIS на Huawei P60 Pro (HarmonyOS 4.2), реальная
загрузка страниц и FrogFind.
