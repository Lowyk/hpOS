# Хранение данных 0.7

Версия 0.7 добавляет постоянное хранение: раздел данных HPFS на загрузочном
диске, драйвер диска через BIOS, службу файловой системы в ring 3,
окно «Файлы» и сохранение настроек рабочего стола.

## Разметка образа

| Область | LBA | Содержимое |
|---|---|---|
| MBR | 0 | загрузочный код и таблица разделов |
| Второй этап | 1–32 | загрузчик BIOS |
| Раздел 1, тип `0xda` | 2048–8191 | ядро со встроенными службами (до 960 КиБ, с 0.10 — до 2,9 МБ) |
| Раздел 2, тип `0x7f` | 8192–65535 | том HPFS, 28 МиБ |

Тип `0x7f` зарезервирован для разработки альтернативных ОС. Сборка форматирует
том заранее: в нём есть папки «Документы» и «Система» и файл
«Документы/Привет.txt». Форматирование выполняет host-пример `crates/fs/examples/mkfs.rs`
тем же Rust-кодом, который работает в ОС.

Ядро больше не ограничено буфером ниже 1 МиБ: второй этап читает его кусками
по 32 КиБ в буфер `0x10000` и переносит выше 1 МиБ через BIOS `INT 15h AH=87h`.

## HPFS

Код — `crates/fs`, без внешних зависимостей и без кучи.

- Блок 4 КиБ. Блок 0 — суперблок с CRC32, блоки 1–8 — 256 инодов по 128 байт.
- Инод хранит тип, родителя, размер, отметку изменения, имя до 63 байт UTF-8,
  16 прямых и один косвенный указатель: файл до 8 МиБ.
- Каталоги не занимают блоков: у каждого инода есть номер родителя.
- Карта свободных блоков не хранится на диске: при монтировании она
  восстанавливается по инодам.
- Содержимое файла заменяется копированием при записи: сначала пишутся
  новые блоки, затем один 512-байтный сектор с инодом. Пока этот сектор не
  записан, старое содержимое остаётся целым. Прерванная запись теряет только
  неиспользованные блоки до следующего монтирования.
- Инод с неверной CRC при монтировании пропускается и учитывается как ошибка.
  Его потомки показываются в корне. Блок, на который ссылаются два файла,
  остаётся за первым.

Ограничения версии: 256 объектов на томе, без журнала, без времени изменения
(отметка — растущий счётчик), имена сравниваются с учётом регистра.

## Драйвер диска

После выхода из BIOS прямых драйверов ATA/AHCI/USB у hpOS нет. Ядро возвращается
в real mode и вызывает `INT 13h` (функции 42h/43h) для загрузочного диска.
Переходник находится в `boot/bios-thunk.S` и копируется по адресу `0x8000`
(код) и `0x9000` (данные). Он сохраняет CR0/CR3, GDT, IDT и сегменты, выключает
страничную адресацию и long mode, вызывает BIOS и возвращает всё обратно.
На время вызова:

- PIC возвращается к векторам BIOS и маскам, снятым при старте ядра;
  IRQ1 и IRQ12 остаются замаскированы, чтобы BIOS не съел байты PS/2;
- PIT возвращается к 18,2 Гц для таймаутов BIOS;
- остальная система стоит: вызов синхронный, один кусок — до 32 КиБ.

После возврата ядро восстанавливает свои векторы, маски, таймер 100 Гц
и перезагружает TR.

Ядро пишет только в раздел типа `0x7f` на загрузочном диске, и только если первый
сектор раздела содержит сигнатуру `HPFS0001`. Другие диски не трогаются.
Если система загружена с мультизагрузочной флешки, где образ hpOS лежит
файлом, своего раздела на этом диске нет, и файлы будут недоступны.

**Shift при загрузке** или **F2 в меню разрешений** запускают систему без
обращения к диску: на случай, если BIOS конкретного ПК плохо переносит
вызовы из ядра.

## Службы

- Ядро: системный вызов 9 (диск) разрешён только службе ФС. Сектора считаются
  от начала раздела; данные идут через её личное окно 64 КиБ.
- Служба ФС (`services/src/fs.rs`): монтирует том и обслуживает запросы рабочего
  стола: STAT, LIST, RESOLVE, CREATE, READ, WRITE, REMOVE, RENAME.
- Запросы передаются через общее окно 64 КиБ, отображённое только в рабочий стол
  и службу ФС; по IPC идёт номер запроса.
- Рабочий стол ждёт ответ до 5 секунд, потом считает службу недоступной.

Стек каждого пользовательского процесса увеличен до 64 КиБ с guard-страницами.

## Интерфейс

- Окно «Файлы» (F4 или значок): папки сверху, затем файлы; путь от «Диск».
  Кнопки: «Вверх», «+ Папка», «+ Файл», «Имя» (переименовать), «Удалить».
- Двойной щелчок или Enter открывает папку, Backspace — на уровень выше,
  колесо прокручивает список.
- Удаление требует второго нажатия «Удалить» или Delete. Непустую папку
  удалить нельзя.
- Имя вводится с клавиатуры: Alt+Shift переключает EN/RU, Caps Lock и Shift
  работают, Backspace стирает, Enter подтверждает, Esc отменяет.
- Тема, акцент и скорость указателя сохраняются в `/Система/settings.ini`
  через 0,6 с после изменения и загружаются при старте.
- В «Системе» показано состояние диска, в «Настройках» — сохраняются ли настройки.

Открывать файлы пока нечем: текстовый редактор — следующий этап.

## Где сохраняются данные

- **Образ записан на флешку напрямую** (весь диск): файлы и настройки
  сохраняются между перезагрузками.
- **Ventoy с Memdisk (Ctrl+D)**: образ целиком в RAM. Файлы работают, но после
  перезагрузки всё возвращается к исходному образу.
- **Ventoy без Memdisk**: раздела hpOS на диске BIOS нет, файлы недоступны.

Запись образа на флешку стирает её целиком. На macOS это делает BSD `dd`
из системы, например `sudo dd if=build/hpos.img of=/dev/rdiskN bs=1m`, где
`N` — номер именно флешки из `diskutil list`.

## Проверено и не проверено

Автоматически проверены: HPFS (форматирование, монтирование, вложенные папки,
большие файлы, сбои записи на каждом шаге, порванный инод, перекрёстные ссылки,
переполнение), разметка образа, суперблок в собранном образе, раскладка данных
переходника, кодирование клавиш, раскладки и сценарии окна «Файлы».
Машинный код переходника просмотрен дизассемблером для всех четырёх режимов процессора.

**Переходник BIOS и драйвер диска не запускались**: в проекте нет эмулятора
без GPL, проверка возможна только на железе.

## Аппаратная проверка

1. Загрузить `build/hpos-0.7.img`. В меню разрешений должна быть строка
   `F2: disk access ON`.
2. «Система»: `ДИСК OK` и `28 МиБ, раздел HPFS`; IPC OK, ISOLATION OK.
3. F4: видны «Документы» и «Система»; в «Документы» — «Привет.txt».
4. Создать папку, файл, переименовать, удалить; переключить EN/RU (Alt+Shift).
5. Поменять тему и акцент, подождать секунду, перезагрузиться: при записи
   на флешку напрямую настройки и созданные папки должны остаться.
6. С Shift при загрузке: система работает, «Диск недоступен».
7. Если система зависает после экрана памяти — сфотографировать экран
   и загрузиться с Shift.
